# ARIA ver.2

ARIA ver.2는 특허 청구항과 인용발명 PDF를 비교하여 신규성·진보성 판단 보고서를 생성하는 로컬 AI 보조 프로그램입니다. ver.2 전용 포트와 실행 스크립트를 사용합니다.

## 비교 입력 전략

설정의 **인용발명 비교 방식**에서 두 모드 중 하나를 선택할 수 있습니다.

- **혼합 모드(기본값)**: 모든 인용발명을 유지하되, 문헌별 관련 문단을 먼저 압축한 뒤 청구항 하나와 함께 한 번의 LLM 호출로 대비합니다.
- **정밀 모드**: 기존 전체 통합 대비 방식입니다. 청구항 하나와 모든 인용발명을 하나의 프롬프트로 묶고, 입력 텍스트가 한도 이내이면 인용발명 전문을 그대로 사용합니다.
- 정밀 모드에서 합산 텍스트가 입력 한도를 넘으면 모든 문헌을 유지하면서 문헌별 관련 문단을 RAG 또는 키워드 기반으로 압축합니다.
- RAG는 BGE-M3 dense 검색과 SQLite BM25 결과를 결합하고, `bge-reranker-v2-m3`로 후보 문단을 재정렬합니다. Qdrant 로컬 인덱스가 실패하면 메모리 dense 검색과 BM25 후보를 사용해 reranker를 계속 적용하며, reranker 실패 시 기존 RRF 순서로 자동 대체됩니다. 추가 LLM 호출은 발생하지 않습니다.
- 비교 방식 또는 판정·보고서 정책 버전이 바뀌면 이전 구성대비·보고서 캐시는 자동으로 갱신됩니다.
- 구성요소 유사도는 `95% 이상 동일 🔵`, `90~94% 실질적 동일(용어 차이만 존재) 🟢`, `85~89% 기술 사상 동일·세부 구현의 단순 변경 🟠`, `80~84% 핵심 기능 유사·목적/효과 일부 차이 🟡`, `80% 미만 대응 안 됨 ⚪` 기준으로 표시됩니다.
- 독립항의 기술적 전제부는 `P` 구성으로 별도 대비하며, 복수 기술수단의 결합·역할분담이 전제부에 있으면 본문 구성과 함께 주 인용발명 선정 점수에 반영합니다.
- 비교 결과는 직접개시·추론 필요·핵심 제한 부재를 구분합니다. 직접 확인되지 않는 제한이 하나라도 있으면 `동일` 또는 `실질적 동일` 판정을 허용하지 않으며, 보고서 판정 퍼센트는 구조화된 비교 판정과 자동으로 일치시킵니다.
- 구성요소별 판정은 해당 라벨에 명시된 구조·기능·관계를 독립적으로 평가하며, 앞선 구성에서 이미 확인한 배열·수치 차이를 후속 구성에 중복 감점하지 않습니다.
- 구성대비 캐시에는 LLM 원판정(`llm_judgment`)과 정책 적용 후 최종판정(`judgment`), 조정 여부 및 조정 사유를 함께 저장하여 판정 하향 경로를 감사할 수 있습니다.
- 종속항 일괄 보고서는 각 종속항의 추가 구성에 대해 입력된 모든 인용발명을 비교한 뒤, 부모항 조합을 상속하고 해당 종속항의 추가 구성에 대응하는 문헌 1개를 새로 결합할 수 있는지 판단합니다. RAG는 문헌 후보를 제외하는 용도가 아니라 각 문헌의 관련 문단을 압축하는 용도로만 사용됩니다.
- 복수의 독립항은 하나의 전역 주·보조 인용발명을 강제로 공유하지 않고, 각 독립항과 그 종속항을 하나의 청구항 패밀리로 묶어 패밀리별 주·보조 인용발명을 선정합니다.
- 관련도 A 인용발명은 독립항에만 표시하며, 해당 독립항의 신규성 또는 진보성 거절근거에 실제 사용되지 않은 문헌만 포함합니다. 각 문헌은 목적·효과 관련 유사점 1줄, 가장 가까운 대응 내용과 한국어 발췌 1줄, 독립항과의 차이점 1줄로 표시하고 구성 라벨은 노출하지 않습니다.
- 독립항 보고서가 한 번 발행되면 그 독립항의 주·보조 인용발명 조합과 전체 문헌 번호 매핑을 사건 데이터에 잠급니다. 이후 종속항을 추가할 때는 기존 인용발명 1·2를 다시 선정·재번호화하지 않으며, 종속항에 필요한 새 문헌만 기존 번호 뒤에 추가합니다. 사용자가 `컨텍스트 클리어`를 실행하면 인용 체인 잠금·문헌 번호·기존 보고서 캐시도 함께 초기화되어 다음 분석에서 인용발명 1부터 새로 선정합니다. 독립항 청구항 문언 또는 구성요소 분해가 변경된 경우에도 해당 패밀리 잠금을 해제하고 다시 선정합니다.
- 주 인용발명은 독립항의 기술적 골격과 핵심 구성 커버리지를 우선하여 선정합니다. 종속항 추가 구성의 폭넓은 개시는 독립항 점수가 근접한 후보 사이에서만 제한적인 타이브레이커로 사용하며, 독립항에 덜 가까운 문헌을 종속항 수만으로 주 인용발명으로 올리지 않습니다.
- 주 인용발명을 먼저 확정한 뒤 보조문헌을 붙이는 방식에만 의존하지 않고, 근접한 주 인용발명 후보별로 가능한 주·보조 문헌 순서쌍을 평가하여 핵심 미커버, 전체 잔여 구성, 직접 발췌 근거를 함께 비교합니다.
- 구성의 존재와 문헌 결합 가능성은 별도로 판단합니다. 보조문헌이 빠진 구성을 개시하더라도 공통 문제·개선 필요성, 입출력 및 처리 관계의 연결 가능성, 기본 작동원리 유지, 반대 교시, 효과의 예측 가능성을 보고서에서 별도로 검토합니다.

## 신규성 우선 판단 및 인용발명 선정 알고리즘

ARIA2는 독립항마다 다음 순서를 고정하여 적용합니다.

1. 청구항 구성요소를 구조, 기능, 조건, 수치, 공간 배열, 축 방향 및 동기 관계의 하위 제한으로 나눕니다. 단일 카메라의 순차 이동과 복수 카메라의 물리적 배열처럼 목적은 비슷하지만 구조가 다른 사항을 구별합니다.
2. 모든 인용발명을 서로 섞지 않고 문헌별로 `직접 개시`, `부분 개시`, `미개시`로 독립 평가합니다. 구체적인 개수·수치·배열·중심 중복·XYZ축 관계는 상위개념만으로 충족시키지 않습니다.
3. 하나의 문헌이 모든 필수 하위 제한과 결합관계를 직접 인용으로 개시하고 누락 제한이 없으면 그 문헌을 신규성 판단용 단일 인용발명으로 확정합니다. 이 단계에서는 복수 문헌을 결합하지 않습니다.
4. 완전개시 문헌이 없을 때만 진보성 경로로 이동합니다. 청구항의 기술적 골격, 핵심 구조·작동관계, 직접 근거의 폭이 가장 가까운 문헌을 주 인용발명으로 선정합니다.
5. 주 인용발명의 실제 잔여 차이를 직접 보완하는 문헌만 보조 인용발명 후보로 평가합니다. 단순히 같은 기술분야이거나 목적이 유사하다는 이유만으로 채택하지 않습니다.
6. 문헌쌍은 `잔여 차이의 보완 범위 → 공통 문제·개선 필요성 → 구조·입출력·처리 흐름의 연결 가능성 → 기본 작동원리 유지 → 반대 교시 → 효과의 예측 가능성` 순서로 검토합니다.
7. 보고서는 결합 후에도 남는 수치, 배열, 축 방향, 동기 관계, 전용 구조와 그 효과를 `잔여 차이 및 방어 포인트`로 표시합니다. 문헌이나 명세서에 없는 효과는 추정하지 않습니다.

선정 과정은 사건 폴더의 `citation_chain.json`에 문헌별 단일문헌 심사 결과, 분석 경로, 주·보조 문헌, 잔여 구성 및 결합 타당성 상태로 저장됩니다.

## 독립항 인용발명 결합 정책

- 독립항의 진보성 판단은 원칙적으로 인용발명 1개와 이를 보완하는 인용발명 1개, 최대 2개를 결합합니다.
- 인용발명 1의 미커버 구성을 실제 발췌 근거로 보완하는 문헌만 인용발명 2로 채택하며, 보완 문헌이 없으면 보완 인용발명 없음으로 표시합니다.
- 구성요소 전체 판정이 `차이`여도 주인용발명의 빠진 하위 제한에 관한 직접 발췌가 있으면 보조 인용발명 후보로 유지합니다. 주인용 공백, 후보별 판정·발췌·하위 제한 근거와 최종 선정 점수는 사건 폴더의 `parsed/citation_chain.json` 및 `parsed/comparison_matrix.json`에 보존합니다.
- 남은 구성이 CPU, 바퀴, 일반 제어부처럼 낮은 중요도의 독립적인 통상 구성이고 특수한 수치·조건·상호작용 제한이 없으면 주지관용 검토 대상으로 분리합니다.
- 해당 통상 구성을 강하게 개시한 문헌이 있으면 `주지관용 구성의 문헌 근거` 역할로 표시하고, 핵심 기술사상의 보완 근거로 확대하지 않습니다.
- 핵심 구성에 이미 인용발명 1과 2가 필요한 경우에만, 남은 통상 구성의 명시 근거로 인용발명 3을 예외적으로 허용합니다.
- 예외적 인용발명 3은 대상 통상 구성에 `동일` 또는 `실질적 동일` 판정과 원문 발췌가 있을 때만 채택합니다.
- 적절한 문헌 근거가 없으면 인용발명 1 또는 인용발명 1·2와 주지관용 검토를 병기하되, 문헌 근거 없이 주지관용이라고 단정하지 않고 추가 입증 필요 여부를 표시합니다.

## 종속항 인용발명 결합 정책

- 종속항은 직접 인용하는 부모항의 인용발명 조합을 전부 상속합니다.
- 종속항 배치 실행 전에 루트 독립항과 중간 부모항의 구성대비 캐시를 확인하며, 정책 버전 변경 등으로 부모항 캐시가 빠졌으면 부모항부터 다시 대비한 뒤 인용 체인을 계산합니다.
- 종속항 전체를 단일문헌 신규성 근거로 표시하려면 부모항도 같은 한 문헌의 직접·완전 개시로 신규성 경로에 있어야 하고, 그 문헌이 종속항의 추가 한정까지 직접 개시해야 합니다. 추가 한정만 일치하는 경우에는 단일문헌 신규성으로 표시하지 않습니다.
- 해당 종속항의 추가 구성에 남은 공백이 있으면, 그 공백 전부를 대응시키는 인용발명 1개만 새로 추가할 수 있습니다.
- 하나의 종속항을 거절하기 위해 새 인용발명 2개 이상을 추가로 결합하지 않습니다. 서로 다른 두 문헌이 있어야 추가 구성이 모두 채워지는 경우에는 해당 조합만으로 거절 근거가 완성되지 않은 것으로 처리합니다.
- 추가 구성과 관련된 발췌가 있더라도 최종 판정이 `차이`이면 실제 결합 인용발명으로 승격하지 않습니다. 최소 `일부 유사` 이상의 대응이 있어야 잔여 차이를 설명하는 부분 근거로 체인에 포함할 수 있습니다.
- 종속항에서 세 번째 이상의 실질적 결합문헌이 추가되면 해당 인용발명 번호를 제목에 그대로 표시합니다. 명시적으로 `주지관용 구성 입증자료` 역할이 부여된 문헌만 주지관용으로 표시합니다.
- 새 인용발명이 추가 구성의 일부만 문언상 직접 개시하더라도, 남는 차이가 이미 개시된 입력·출력·처리부·적용 대상에 대한 통상적인 전처리·후처리, 데이터·신호·물질·부품의 변환·보정·정렬·조정, 공지된 계산·제어·제조·조립·분석 방법의 적용이면 거절 근거를 구성할 수 있는 방향으로 검토합니다.
- 따라서 독립항이 인용발명 1·2로 검토되고 청구항 2가 인용발명 3을 추가하면 청구항 2의 최종 조합은 1·2·3입니다. 청구항 2를 인용하는 청구항 3은 여기에 인용발명 4를 하나 더 추가할 수 있고, 독립항을 직접 인용하는 별도 청구항은 1·2에서 다시 시작해 자기 추가 구성에 대응하는 문헌 1개만 더합니다.

종속항 정량평가는 부모항 전체를 다시 점수화하지 않고 해당 종속항에 새로 부가된
한정만 대상으로 내부 산정합니다. 보고서에는 별도 정량평가 항목을 표시하지 않고,
미커버 구성 검색과 사건 데이터 감사에 필요한 값만 저장합니다.

새 인용문헌은 상속 문헌 대비 추가 한정의 순수 커버리지 증가와 인용문·위치·판단
근거의 존재를 기준으로 선정합니다. 하나의 문헌이 잔여 추가 한정을 모두 보완하는
경우와 일부만 보완하는 경우를 구분하고, 후자는 완전 대응으로 표시하지 않습니다.
사건 데이터에는 후보별 증가분, 근거 조정 증가분, 대응 라벨 및 최종 선정 경로가
`decision_trace`로 저장됩니다. 특정 모델명이나 기술분야 키워드에는 가산점을 주지
않습니다.

추가 문헌 후보의 해당 종속항 점수가 같으면, 다른 종속항의 추가 한정에도 직접 발췌
근거를 제공하는 문헌을 재사용성 타이브레이커로 우선합니다. 재사용성은 더 강한 직접
근거를 가진 문헌을 밀어내는 주점수가 아니며, 동점 후보의 사건 전체 일관성을 높이는
용도로만 사용됩니다.

결합형 보고서는 각 구성요소에서 주 인용발명 기준 판정을 유지하되, 주 인용발명에
미개시 또는 약한 하위 제한이 있으면 같은 구성요소의 `보완 검토`에 보조문헌 원문,
보완 범위 및 보완 후 잔여 제한을 표시합니다. 최종 종합분석에서는 구성 보완과 결합
동기·기술적 양립성을 분리하여 판단합니다.

## 미커버 구성 선행기술 검색

- 보고서의 `부족한 구성 검색` 버튼은 내부 정량평가에서 미커버로 남은 구성만 웹에서 검색합니다.
- 범용 기능, 특허, 학술논문 검색을 동시에 실행하고 직접 URL·문헌 식별자가 부족할 때만 동의어 확장 검색을 한 번 추가합니다.
- 검색 요청에는 해당 청구항, 미커버 구성, 이미 사용된 문헌 및 사용자가 입력한 추가 검색 조건이 포함됩니다.
- 검색 결과는 후보 문헌별 카드로 분리되며, 각 카드에 `문헌번호(이름)`, 최초 공개일, 대응 내용 및 남는 차이가 표시됩니다. `직접 링크`에는 복사할 수 있는 전체 URL 문자열을 그대로 표시합니다.
- `문헌번호(이름)`에는 특허 후보는 공개번호를, 논문 후보는 DOI나 저널 식별정보 대신 논문의 정식 제목을 표시합니다.
- 검색 결과는 별도 결과 화면에 표시되고 케이스별 JSON과 브라우저 히스토리에 저장되어, 해당 청구항의 히스토리를 선택하면 다시 볼 수 있습니다.
- 현재 웹 검색 도구는 Claude 또는 AGY 엔진에서 사용합니다. OpenAI CLI 실행 경로에서는 검색을 실행하지 않고 엔진 변경 안내를 표시합니다.
- 이 빠른 검색은 원문 전체 구성대비나 정밀 메타데이터 감사를 수행하지 않습니다. 후보는 기존 인용문헌에 자동 편입되지 않으며 별도 검토가 필요합니다.

## 주요 기능

- 인용발명 PDF 최대 7개 업로드 및 텍스트·문단·페이지 정보 추출
- 사용자가 붙여넣은 청구항을 구성요소 단위로 분해
- 구성요소별 인용발명 대비 결과와 최종 거절이유 보고서 생성
- 구성대비의 `인용발명 대응 원문`에는 발췌문과 위치만 표시하며, `~고 기재되어 있습니다` 같은 반복적인 보고형 문구는 붙이지 않습니다.
- 독립항·종속항 흐름을 반영한 일괄 보고서 생성
- Claude CLI, OpenAI Codex CLI 또는 AGY CLI 기반 LLM 실행
- 보고서 Q&A 지원
- PyMuPDF 우선 추출, OpenDataLoader PDF fallback, SQLite/Qdrant 기반 RAG 저장 구조

## 기본 사용 흐름

1. 인용발명 PDF를 업로드하고 준비 작업을 실행합니다.
2. 청구항 번호와 청구항 전문을 입력합니다.
   - 복수 청구항 헤더는 `청구항 N`, `제N항`, `【청구항 N】`, `[CLAIM N]` 형식을 인식합니다.
   - 종속항이 참조하는 부모항이 입력 또는 이전 컨텍스트에 없으면 부모항의 실체를 추정하지 않고, `에 있어서` 뒤에 직접 기재된 기술 특징만 인용발명과 대비합니다.
3. 필요하면 설정에서 `혼합 모드` 또는 `정밀 모드`를 선택합니다.
4. 보고서를 생성하여 최상단 거절 유형 라벨과 구성요소 대비 보고서를 확인합니다.
5. 필요한 경우 Q&A 패널로 판단 근거를 확인합니다.
