# ARIA (Patent Search & Analysis Assistant)

**ARIA**는 특허 청구항과 인용발명 PDF를 비교 분석하여 **신규성 및 진보성 판단 보고서**를 자동 생성하는 로컬 AI 보조 프로그램입니다.

---

## 🚀 빠른 시작 (Quick Start)

### 1. 요구 사항
- **Python**: 3.10 이상
- **Node.js**: 18 이상
- **LLM CLI**: Claude CLI, OpenAI Codex CLI 또는 AGY CLI

### 2. 원클릭 실행 (Windows PowerShell)
```powershell
.\start.ps1
```
*`start.ps1` 스크립트는 백엔드 의존성 설치, FastAPI 서버 및 Vite 프론트엔드를 한 번에 실행합니다.*

### 3. 접속 포트
| 구분 | 주소 | 비고 |
| :--- | :--- | :--- |
| **Frontend** | `http://localhost:5274` | 웹 UI 접속 |
| **Backend API** | `http://localhost:8200` | FastAPI 서버 |

## 💡 기본 사용 흐름

1. **인용발명 PDF 업로드**: 비교할 인용발명 PDF 문헌(최대 7개)을 업로드하고 텍스트 추출 및 분석 준비를 실행합니다.
2. **청구항 입력**: 분석할 청구항 번호와 청구항 전문을 붙여넣습니다.
   - *인식 가능 헤더*: `청구항 N`, `제N항`, `【청구항 N】`, `[CLAIM N]`
   - *참고*: 종속항이 참조하는 부모항이 미입력된 경우 `에 있어서` 뒤의 직접 기재 기술 특징만 인용발명과 대비합니다.
3. **비교 모드 선택** (필요시 설정에서 변경):
   - **혼합 모드 (기본값)**: 독창적 핵심 구성을 먼저 비교 후 상위 문헌 중심으로 범용 구성을 효율적으로 배치 대비
   - **정밀 모드**: 청구항과 모든 인용발명을 전문 통합 프롬프트로 묶어 정밀하게 분석
4. **보고서 생성**: 거절 이유 유형 라벨 및 구성요소별 인용발명 대비 상세 보고서를 확인합니다.
5. **Q&A 및 선행기술 검색**: Q&A 패널로 판단 근거를 세부 확인하거나, 미커버 구성에 대한 웹 선행기술 검색을 수행합니다.

## ✨ 주요 기능 요약

- **PDF 자동 추출 & 사건별 원문 보관**: PyMuPDF / OpenDataLoader로 텍스트를 추출하고, 단락·청크·인용 항목을 사건별 SQLite에 보관해 판단 근거를 원문과 대조·재현
- **특허문헌/비특허문헌 자동 판별**: KR·US·WO(PCT)·EP·JP·CN 공보 서지사항과 단락번호로 특허문헌을 식별하고, 그 외 문헌은 비특허문헌(논문) 본문 청킹 경로로 처리
- **청구항 구성요소 자동 분해**: 독립항/종속항의 구조, 기능, 조건, 수치, 공간배열, 축 방향 등 하위 제한 단위 분해
- **독립항·종속항 체인 반영**: 부모항 인용 체인을 상속하여 합리적인 주·보조 인용발명 조합 결합
- **결정론적 판정 & 원문 검증**: 발췌문 원문 대조, 외국어 문헌 원문/번역 병기, 신규성/진보성 판단 하향 사유 감사 기능(`decision_trace`)
- **다양한 LLM 엔진 지원**: Claude CLI, OpenAI Codex CLI, AGY CLI 지원
- **미커버 구성 선행기술 빠른 검색**: 심사 중 미커버로 남은 핵심 구성에 대해 특허/학술논문 웹 검색 지원

## ⚙️ 특허 비교 분석 및 판정 정책

<details>
<summary><b>1. 비교 입력 전략 (혼합 모드 vs 정밀 모드)</b></summary>

- **혼합 모드(기본값)**: 큰 독립항 비교 시 독창적 핵심 구성을 축소된 문헌 예산으로 모든 인용발명과 먼저 대비한 뒤, 핵심 점수 상위 주 인용발명 후보에 대해서만 단순 범용 구성을 한 번에 배치 대비합니다. 작은 사건과 종속항은 기존 통합 비교를 유지합니다.
- **비특허문헌 본문 청킹 비교**: 비특허문헌(논문)은 섹션 표제를 인식해 초록·참고문헌·감사의 글을 비교 대상에서 제외하고, 기술 본문을 약 2천 자 단위의 중첩 청크로 구성합니다. 섹션 인식이 실패해 본문 전체가 초록으로 묶이는 경우에도 앞부분 약 3천 자까지만 초록으로 제외해 본문이 통째로 누락되지 않게 합니다. 청구항 구성별 적중 청크와 앞뒤 청크를 최대 약 3만 자 예산으로 묶어 다른 인용발명과 통합 대비하며, 누락 가능성이나 근거 품질 문제가 탐지된 구성만 제한적으로 정밀 재검토합니다.
- **정밀 모드**: 기존 전체 통합 대비 방식입니다. 청구항 하나와 모든 인용발명을 하나의 프롬프트로 묶고, 입력 텍스트가 한도 이내이면 인용발명 전문을 그대로 사용합니다.
- **입력 예산 초과 시 압축**: 합산 텍스트가 엔진별 한도를 넘으면 문헌별 예산을 나눈 뒤, 청구항 키워드(한국어·영어·일본어·중국어 확장)가 적중한 청크와 그 앞뒤 청크를 예산까지 모아 씁니다. 임베딩 벡터 검색이나 재순위 모델은 사용하지 않습니다.
- **유사도 판단 기준**:
  - `🔵 95% 이상`: 동일
  - `🟢 90~94%`: 실질적 동일 (용어 차이만 존재)
  - `🟠 85~89%`: 기술 사상 동일 · 세부 구현의 단순 변경 (일부 차이)
  - `🟡 80~84%`: 핵심 기능 유사 · 목적/효과 일부 차이 (일부 유사)
  - `⚪ 80% 미만`: 대응 안 됨 (차이 / 대응 없음)
- **대표값 매핑**: 퍼센트는 연속 계산값이 아닌 백엔드에서 고정된 대표값(`동일 97%`, `실질적동일 92%`, `일부차이 87%`, `일부유사 82%`, `차이 70%`, `대응 없음 0%`)으로 표출됩니다.
- **원문 발췌 검증**: 캐시 저장 전 대표 발췌문과 원문 간 문자열 대조를 수행하여 단순 합성 문장은 직접 인용으로 인정하지 않으며 정확한 원문 발췌로 복구 및 검증합니다.
- **비특허문헌 근거 품질 게이트**: 비특허문헌 근거는 주체·입력·처리·출력·조건·결합관계 및 페이지·섹션을 구조화해 저장합니다. 제목·캡션의 짧은 명사 나열이나 기능사슬이 없는 높은 판정은 실패 구성만 최대 1회 재검토하고, 계속 불충분하면 수동 검토 대상으로 표시합니다.
</details>

<details>
<summary><b>2. 신규성 우선 판단 및 인용발명 선정 알고리즘</b></summary>

독립항마다 다음 순서를 고정하여 적용합니다:
1. **청구항 구성요소 분해**: 구조, 기능, 조건, 수치, 공간 배열, 축 방향 및 동기 관계 등 하위 제한 단위로 세분화.
2. **독립 평가**: 모든 인용발명에 대해 `직접 개시`, `부분 개시`, `미개시`를 개별 평가.
3. **단일문헌 신규성 판단**: 한 문헌이 모든 필수 하위 제한 및 결합관계를 직접 개시하고 누락 제한이 없으면 단일 인용발명 신규성 거절로 확정. 이 게이트를 통과하면 문헌 결합과 아래 판정 단계를 모두 건너뜁니다.
4. **주 인용발명 자격 게이트**: 차별적 핵심 구성의 직접 개시량이 최고 문헌에 크게 못 미치는 문헌은 주 인용발명 후보에서 제외합니다. 다만 전체 점수가 낮아도 차별적 핵심을 원문으로 직접 개시한 문헌은 항상 후보로 남겨, 평균 점수에 희석되어 유효한 후보가 탈락하지 않게 합니다.
5. **주 인용발명 최종 선정(LLM-A)**: 자격 게이트를 통과한 후보가 2개 이상이면, 계산된 커버리지 지표와 원문 발췌를 근거로 LLM이 후보 **안에서만** 최종 선정합니다. 후보가 1개면 호출하지 않습니다. 응답이 후보 밖 문헌을 지목하거나 파싱에 실패하면 알고리즘 1순위로 되돌립니다.
6. **보조 인용발명 선정**: 확정된 주 인용발명의 잔여 차이를 직접 보완하는 문헌만 후보로 채택합니다. 반대 교시·기본 작동원리 변경·비양립이 명시된 문헌은 후보에서 제외합니다. 보조 후보 점수는 절대 성능이 아니라 **주 인용발명 대비 증분**으로 계산합니다.
7. **결합 가능성 기술 검토(LLM-B)**: 기술분야 인접성 · 입출력 호환성 · 치환/부가 가능성 · 기술적 모순 · 명시적 결합 시사를 각각 **사실 항목으로만** 판정합니다. `결합 근거` 등급(`explicit` / `implicit` / `unproven`)은 그 값들로부터 백엔드가 결정론적으로 조립하며, LLM이 결론을 직접 내지 않습니다. 결합을 시사한다고 제시한 발췌의 `chunk_id`가 실제 원문에 없으면 명시적 근거로 인정하지 않습니다.
8. **결합 타당성 검토**: `잔여 차이 보완 범위 → 공통 문제/개선 필요성 → 연결 가능성 → 기본 작동원리 유지 → 반대 교시 여부 → 효과의 예측 가능성` 순서로 검토.
9. **결과 저장**: 분석 경로는 사건 폴더의 `citation_chain.json`에 보존됩니다. 후보 목록, 알고리즘 순위와 LLM 선택의 차이, 점수 마진, 폴백 사유가 `llm_adjudication.audit`에 함께 기록됩니다.

**재현성**: 판정 결과는 `청구항 + 구성대비 판정 + 후보 목록 + 프롬프트 버전 + 모델`의 해시를 키로 `data/adjudication_cache/`에 저장됩니다. 사건 폴더 밖이므로 히스토리를 삭제해도 같은 입력이면 같은 판정이 재사용됩니다. 커버리지 계산·후보 확정·보고서 문장 생성은 전부 LLM 없이 수행되므로 `backend/tests/goldens/` 회귀 테스트로 검증됩니다.
</details>

<details>
<summary><b>3. 독립항 인용발명 결합 정책</b></summary>

- **기본 결합 한도**: 독립항 진보성 판단은 원칙적으로 주 인용발명 1개 + 보완 인용발명 1개(최대 2개) 결합을 사용합니다.
- **주지관용 구성 분리**: 남은 미커버 구성이 CPU, 바퀴, 일반 제어부 등 낮은 중요도의 일반적인 구성인 경우 주지관용 검토 대상으로 분리합니다.
- **예외적 3개문헌 결합**: 핵심 구성에 이미 인용발명 1·2가 사용되고, 남은 통상 구성에 명시적 원문 발췌 근거가 있는 경우에 한해 예외적으로 인용발명 3을 채택합니다.
</details>

<details>
<summary><b>4. 종속항 인용발명 결합 정책</b></summary>

- **인용 체인 상속**: 종속항은 부모항의 인용발명 조합을 기본적으로 상속합니다.
- **추가 문헌 결합 제한**: 종속항의 추가 한정에 남은 공백이 있을 때, 해당 공백을 모두 채우는 **단 1개의 새 인용발명만 추가**할 수 있습니다. (하나의 종속항 거절을 위해 새 문헌 2개 이상 추가 불가)
- **조합 예시**: 독립항(문헌 1·2) ➔ 청구항 2가 문헌 3 추가 ➔ 청구항 2 조합(1·2·3) ➔ 청구항 2를 참조하는 청구항 3은 문헌 4를 추가하여 조합(1·2·3·4) 완성.
</details>

<details>
<summary><b>5. 미커버 구성 선행기술 웹 검색</b></summary>

- 보고서의 **[부족한 구성 검색]** 버튼을 통해 내부 심사에서 미커버로 남은 구성만 선택적으로 웹(특허, 학술논문) 검색합니다.
- 검색 결과는 문헌번호(공개번호 또는 논문 정식 제목), 최초 공개일, 대응 내용, 남은 차이점 및 직접 링크 URL 카드로 제공됩니다.
- 검색 결과는 사건별 JSON 및 브라우저 히스토리에 보관됩니다. *(Claude/AGY 엔진 지원)*
</details>

## 🛠️ 개발 및 개별 실행 방법

### Backend 실행
```powershell
# Windows 환경에서 한글 로그 깨짐 방지를 위한 UTF-8 설정
$env:PYTHONUTF8="1"
$env:PYTHONIOENCODING="utf-8"

pip install -r backend/requirements.txt
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8200 --reload --reload-dir backend
```
*참고: 백엔드 개발 서버는 `backend` 디렉토리 소스 변경만 감시하므로 임시 분석 스크립트에 의해 서버가 재시작되지 않습니다.*

### Frontend 실행
```powershell
cd frontend
npm install
npm run dev
```
